# XSD Elements Reference

This document provides a comprehensive reference of all XML elements and their available attributes.

---

## `<binary>`

**Type:** `Binary`

Binary type field (binary data, e.g. image, pdf etc).

### Attributes

- **`name`** (**required**)
  - Name of the field (should start with lower case letter).
  - Pattern: `([a-z][a-zA-Z0-9_]+)|([A-Z][A-Z0-9_]+)`

- **`column`** (*optional*)
  - Type: `string`
  - Name of the column in the underlying database table (should be defined when the field name is reserved word in database systems).<br><br> When used on many-to-many with 'table' attribute, it's used as the foreign key column in the underlying database table referring the owning table.

- **`title`** (*optional*)
  - Type: `string`
  - Title text to be used by UI components.

- **`help`** (*optional*)
  - Type: `string`
  - Help text to be used by UI components.

- **`required`** (*optional*)
  - Type: `boolean`
  - Whether the field is required or allow null value.

- **`readonly`** (*optional*)
  - Type: `boolean`
  - Whether the field should be considered readonly by UI components.

- **`hidden`** (*optional*)
  - Type: `boolean`
  - Whether the field should be hidden in UI components.

- **`transient`** (*optional*)
  - Type: `boolean`
  - Specifies that the field is not persistent (not stored in database).

- **`default`** (*optional*)
  - Type: `string`
  - Default value for the field.

- **`unique`** (*optional*)
  - Type: `boolean`
  - Whether the field value should be unique (unique constraint will be created on database table).

- **`initParam`** (*optional*)
  - Type: `boolean`
  - Whether the field should be used as a constructor parameter.<br><br> If there are some fields with this attribute having `true` value then a constructor is generated using all those fields as constructor parameters.

- **`index`** (*optional*)
  - Whether to create index on database table (optimizes search query). You can provide custom index name here (starting with 'idx_' prefix), else default index name is generated using table name and column name.
  - Pattern: `(true|false|idx_[\w|_]+)`

- **`massUpdate`** (*optional*)
  - Type: `boolean`
  - Default: `false`
  - Whether to allow mass update on this field (default false).

- **`copy`** (*optional*)
  - Type: `boolean`
  - Default: `true`
  - Whether to use this field when creating duplicate record?

- **`insertable`** (*optional*)
  - Type: `boolean`
  - Whether the column is included in SQL INSERT statements generated by the persistence provider.

- **`updatable`** (*optional*)
  - Type: `boolean`
  - Whether the column is included in SQL UPDATE statements generated by the persistence provider.

- **`image`** (*optional*)
  - Type: `boolean`
  - Whether the field is intended to store image data.

- **`encrypted`** (*optional*)
  - Type: `boolean`
  - Specify whether the field is encrypted.

- **`default`** (*optional*)

- **`readonly`** (*optional*)

- **`unique`** (*optional*)

- **`hidden`** (*optional*)

- **`massUpdate`** (*optional*)

## `<entity>`

**Type:** `Entity`

Define an Entity (domain model).

### Attributes

- **`name`** (**required**)
  - Name of the Entity (should begin with upper case letter).
  - Pattern: `[A-Z][a-zA-Z0-9_]+`

- **`table`** (*optional*)
  - Table name for the entity.
  - Pattern: `([a-zA-Z]\w+)(_\w+)*`

- **`sequential`** (*optional*)
  - Type: `boolean`
  - Whether the records of this entity should be in unique sequence (else a global sequence will be used).

- **`jsonAttrs`** (*optional*)
  - Type: `boolean`
  - Specify whether the entity should have 'attrs' json field.

- **`logUpdates`** (*optional*)
  - Type: `boolean`
  - Default: `true`
  - Whether to log `creation date, last modified date, user who created the record and user who modified it last` information. The information is stored in these four fields respectively `createdOn, updatedOn, createdBy, and updatedBy`

- **`equalsIncludeAll`** (*optional*)
  - Type: `boolean`
  - Whether to include all the simple non-function fields in equality test. You can still ignore some fields with equalsInclude="false" attribute.

- **`cacheable`** (*optional*)
  - Type: `boolean`
  - Specifies whether the entity should be cached if caching is enabled.

- **`persistable`** (*optional*)
  - Type: `boolean`
  - Default: `true`
  - Specify whether this entity is persistable (in database). Non-persistable entity classes as annotated with @MappedSuperclass and can be used as base class of other entities.

- **`implements`** (*optional*)
  - Type: `string`
  - Specify the list of interfaces to implement.

- **`extends`** (*optional*)
  - Type: `string`
  - Specify the base entity class.

- **`strategy`** (*optional*)
  - Specify the inheritance strategy (default is SINGLE).
  - Possible values: SINGLE, JOINED, CLASS

- **`repository`** (*optional*)
  - Possible values: none, default, abstract

## `<finder-method>`

**Type:** `Finder`

Define a finder method.

### Attributes

- **`name`** (**required**)
  - Type: `string`
  - Name of the finder method. As a convention, always use `findBy` prefix.

- **`using`** (**required**)
  - Type: `string`
  - Provide the method parameters (comma seperated list). A parameter can be a field name defined above or/and a definition in the format `type:name` where `type` can be either of the following type.<br> <ul> <li>int, long, double, boolean</li> <li>Integer, Long, Double, Boolean</li> <li>String, BigDecimal</li> <li>LocalDate, LocalTime, LocalDateTime, DateTime</li> </ul> <br> <br> If all the all the parameters are field names and filter is not given then an ANDed filter on the given names is generated. <br> <br> Some examples:<br><br> ... using="code, name"<br> ... using="long:customerId,String:email"<br> ... using="long:customerId,String:email,totalAmount"

- **`filter`** (*optional*)
  - Type: `string`
  - Use the given filter. The filter expression should only use the given field names as named parameters. Some examples: <br> <br> ... using="code, name" filter="self.name = :name OR self.code = :code" <br> <br> ... using="long:id, String:email" filter="self.customer.id = :id OR self.customer.email = :email"

- **`orderBy`** (*optional*)
  - Type: `string`
  - Return the result with given orderning. For example: orderBy="-name,code"

- **`all`** (*optional*)
  - Type: `boolean`
  - Default: `false`
  - If true, then the finder method returns a Query instance on which you can call any of the fetch method. By default first matched object is returned.

- **`cacheable`** (*optional*)
  - Type: `boolean`
  - Default: `false`
  - Whether to make the finder query cacheable (default false).

- **`flush`** (*optional*)
  - Type: `boolean`
  - Default: `true`
  - Whether to mark query flush mode to auto (default is true).

**Type:** `Index`

Define an index on the specified column(s).

### Attributes

- **`name`** (*optional*)
  - Type: `string`

- **`unique`** (*optional*)
  - Type: `string`

- **`columns`** (**required**)
  - Comma separated list of field names. The column names can be followed by either ASC or DESC. If ASC or DESC is not specified, ASC is assumed. Some examples: columns="code,name" columns="code ASC,name DESC" columns="code,name DESC"
  - Pattern: `([a-zA-Z][a-zA-Z0-9_]+(\s+(ASC|DESC))?)(,([a-zA-Z][a-zA-Z0-9_]+(\s+(ASC|DESC))?))*`
