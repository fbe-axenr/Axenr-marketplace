# PR Description Template

This template is used by the pr-analyzer skill to generate comprehensive PR descriptions.

## Structure

```markdown
## Summary
{Brief description of what this PR does}

**Impact**: {X} files changed (+{additions} additions, -{deletions} deletions, +{net} net)
**Risk Level**: {Low/Medium/High/Critical}
**Review Time**: ~{minutes} minutes

## What Changed

### {Category} ({count} files)
- `{file_path}` - {Brief description of changes}
...

## Type of Change
- [x] {Primary type}
- [ ] Other types...

## How Has This Been Tested?

### Test Coverage
- **Before**: {coverage}%
- **After**: {coverage}%
- **Change**: {+/-X}%

### Test Types
- {Description of tests}

### Manual Testing
- [ ] {Test scenario 1}
- [ ] {Test scenario 2}

## Risk Assessment

### Overall Risk: {LEVEL}

**{Risk Factor}**: {Level}
- {Details}

### Mitigation Strategies
1. {Strategy 1}
2. {Strategy 2}

## Breaking Changes

{List breaking changes or "None"}

## Visual Changes

{Mermaid diagrams for architecture/flow changes}

## Performance Impact

{Performance considerations or "None identified"}

## Dependencies

### Added
- {package@version} - {purpose}

### Updated
- {package@version} - {purpose}

- {package@version} - {reason}

### {Context-specific category}

---

**Generated by PR Analyzer**
**Review this description and adjust as needed before creating the PR**
```

## Categories

File changes are organized into these categories:

1. **Source Code**: Production code files
2. **Tests**: Test files (unit, integration, e2e)
3. **Configuration**: Config files (JSON, YAML, properties, env)
4. **Documentation**: Markdown, text, docs
5. **Styles**: CSS, SCSS, Less
6. **Build**: Build configuration (Gradle, Maven, package.json)
7. **CI/CD**: CI/CD configuration files
8. **Database**: Migrations, models, schemas

## Risk Level Definitions

- **Low**: Small change, well-tested, low impact
- **Medium**: Moderate change, multiple files, some complexity
- **High**: Large change, many files, complex logic, or missing tests
- **Critical**: Very large change, security implications, or significant breaking changes

## Review Time Estimation

Based on file count and complexity:

- Small (1-3 files, <100 lines): ~5-10 minutes
- Medium (4-10 files, 100-300 lines): ~15-25 minutes
- Large (11-20 files, 300-600 lines): ~30-45 minutes
- Very Large (20+ files, 600+ lines): ~60+ minutes

## Checklist Categories

Context-aware checklists are generated based on changed files:

- **General**: Always included
- **Code Quality**: When source files changed
- **Security**: When auth, crypto, or sensitive code changed
- **Testing**: When tests are present
- **Configuration**: When config files changed
- **Documentation**: When docs changed
- **Performance**: When database or performance-critical code changed
- **Database**: When migrations or models changed
- **API**: When API endpoints changed
